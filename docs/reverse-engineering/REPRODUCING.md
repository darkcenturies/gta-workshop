# Reproducing the archive

The generated archive remains public. Authored exporter/analysis scripts were
preserved in private Valkyrie Workshop. Commands and paths below describe that
private historical source, not scripts included in this public knowledge tree.
Use a private archive worktree when reproducing the exact recorded method.
Compare file hashes against checksums.json and SHA256SUMS before submitting.


The archived run used Ghidra 12.1.3 and ExportDecompiled.py. The historical checkpoint records JDK 21 and PyGhidra 3.1.0. Re-running may produce differences across environments; preserve the original checked-in records and explain changes.

1. Obtain the matching input separately and compare its byte size and SHA-256 against generated/index.json or research/targets.json.
2. Install Ghidra, JDK and PyGhidra locally. Copy deploy/reverse-targets.example.json to work/reverse-targets.json and set each source.path to your input's absolute local path. The example contains only the six completed targets.
3. Run PowerShell 7 with explicit local tool paths:

```powershell
./deploy/decompile-ssmp-pe.ps1 -GhidraHome C:/Tools/ghidra -JdkHome C:/Tools/jdk-21 -PyGhidraPython C:/Tools/pyghidra/Scripts/python.exe -TargetManifest ./work/reverse-targets.json -Only ssmp-server-1.3.1-patch1
```

The historical wrapper writes new output under work/reverse-engineering/generated by default and refuses to replace an existing target directory. Choose a fresh OutputRoot for another run. It checks input size/hash and output metadata. It does not fetch binaries, connect to a server or publish results.

For optional GTA symbol naming, obtain the separately referenced gta-reversed revision and run:

```sh
python deploy/name-decompiled.py work/reverse-engineering/generated/gta-sa-1.0-us --reference-source /path/to/gta-reversed/source
```

Review regenerated changes before moving them into the public archive. Verify archive integrity with `sha256sum -c docs/reverse-engineering/SHA256SUMS` from the public repository root (Git Bash/Linux). If intentionally changing archive files, update checksums.json and include target/version evidence in the pull request. checksums.json records archive file hashes, whereas metadata.json records the input binary hash.

This publication verifies the existing archived outputs; it does not rerun hours of decompilation or claim a newly completed target.
