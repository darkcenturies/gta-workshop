# Follow a task through the workshop

These are routing examples, not claims that new builds or experiments ran.
Use the [task-flow map](task-flow.svg), [component catalog](CATALOG.md) and
[agent completion requirements](../../AGENTS.md) for actual work.

## Doctor crash investigation: existing public scope

1. Start here, read the Doctor/Crashfix source guide, and identify the exact
   classic SA executable and observed failure. Do not infer compatibility from
   a generic product/version name.
2. Consult the relevant Ghidra Bridge, ReAgent and native SDK references. Record
   which tools were actually run; a reference review is not a reconstruction.
3. Investigate bounded archive evidence and change the approved public component
   here. Preserve combined licensing and the single artwork-free ASI behavior.
4. Run public boundary/archive checks, affected builds and relevant guard tests.
   Distinguish isolated results from unperformed game testing.
5. Commit and push the code/finding contribution; open the public PR. Return
   failed hypotheses, exact evidence, actual checks and remaining game cases
   in the same repository. Merge/release/deployment states remain separate.

## SRG / GTA Midnight change: private source with a public return

1. Start with the public project description; sensitive request details go
   directly to SRG's private owner. Read its instructions and chosen component.
2. Pick relevant Ariane/Scout/Flow/native/limit references for the specific task.
   Resolve target/profile limits before authoring or runtime assumptions.
3. Implement in SRG. A shared Core correction belongs in Workshop; coordinate
   its own commit and consumer validation rather than creating another Core copy.
4. Keep generated assets, local game inputs and full restricted findings in the
   owner's permitted locations. Run the affected runtime/format/consumer checks.
5. Commit/push private work according to the owner, and separately commit/push
   a sanitized workshop finding with the outcome, actual validation, limits and
   private-source withholding reason. A public branch never stages SRG source.

## New CLEO example: proposed public component

1. Define an original or synthetic public example and review its scope and
   applicable terms before including new source/paths here.
2. Consult CLEO AI and its exact opcode/profile documentation. Record lookup,
   generation, validation and compilation separately.
3. Capture reproducible permitted inputs and actual outputs/checks. Record game
   testing separately; successful compilation is not multiplayer support.
4. Review notices and the destination allowlist, then commit/push the example
   and finding through a PR. If evaluation fails or is blocked, still return
   the useful negative result and pending step.

## Upstate/re3 change: external engine and private owned patch

1. Route to Workshop's Upstate owner; read its exact engine base and build guide.
2. Keep the public third-party re3 source distinct from our private compatibility
   patch, mod author credits, CLEO Redux scripts and locally supplied game assets.
3. Use the owner's engine/format/toolchain checks. CLEO AI's GTA SA script
   validation does not validate a re3 CLEO Redux script or engine patch.
4. Commit/push the owned change in Workshop and return safe engine/patch
   revisions, actual build/roundtrip results and campaign/save limitations here.
   A source export of our patch is a separate publication decision.

## Generic server improvement or graphics experiment

1. Route gameplay to SP-RP, native components to Workshop, rendering to its
   private kit, and service changes to their respective owners.
2. For server research, compare relevant R5 or MTA references without treating
   those platforms as proven S&SMP compatibility. For graphics, a SkyGfx
   reference does not establish DLSS host/driver support.
3. Run the owner's applicable checks using sanitized/synthetic inputs where
   possible. Keep player records, raw private logs and production configuration
   out of public reproductions.
4. Commit/push the owner contribution and return a safe finding here. A generic
   source example needs publication review; any live deployment needs its own
   authorized owner process and returned evidence.
